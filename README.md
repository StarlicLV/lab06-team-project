## Опис

Сторінка `/api-demo` працює з REST API кав'ярні (лабораторна 5) за допомогою JavaScript і `fetch`.
Список товарів завантажується з API без перезавантаження сторінки, нові товари додаються через форму,
а результат (успіх або помилка) показується повідомленням. Сторінка працює в світлій і темній темі.

**Технології:** Python, Flask, Tailwind CSS, JavaScript (`fetch`, `async/await`).

## Запуск

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt
python app.py
```

Сторінка: `http://127.0.0.1:5000/api-demo`. Сторінку віддає той самий Flask-сервер, що й API,
тому запити на `/api/v1/products` не виходять за межі одного джерела і налаштовувати CORS не потрібно.

## Структура

```text
templates/api-demo.html        розмітка сторінки (форма, список, місця для повідомлень)
static/js/api-demo.js          список товарів, допоміжні функції
static/js/api-demo-form.js     форма додавання товару
static/css/api-demo.css        картки товарів, стани форми та індикатор завантаження
app.py                         маршрут /api-demo
```

## Які endpoints використовує сторінка

| Метод | Адреса | Призначення | Коди відповідей |
|---|---|---|---|
| GET | `/api/v1/products` | отримати список товарів | 200 |
| POST | `/api/v1/products` | додати новий товар | 201, 400, 415 |

Відповідь на GET має вигляд `{"count": 3, "products": [...]}`.

Поля товару при створенні:

| Поле | Тип | Правило |
|---|---|---|
| `name` | рядок | обовʼязкове, до 100 символів |
| `price` | число | обовʼязкове, не менше 0 |
| `category` | рядок | обовʼязкове, до 100 символів |
| `description` | рядок | необовʼязкове, до 1000 символів |
| `is_available` | true / false | необовʼязкове, за замовчуванням true |

## Обробка помилок

Помилки сервера приходять у форматі JSON, а сторінка показує їх користувачу:

```json
{"error": "Помилка валідації даних", "status": 400, "details": {"price": "Має бути числом не менше 0"}}
```

Окремо оброблено випадок, коли сервер недоступний: замість порожньої сторінки користувач бачить повідомлення про помилку з'єднання.
Усі дані на сторінці виводяться як текст, а не як HTML, тому введені користувачем теги не виконуються.

## Висновки

Під час роботи ми підключили сторінку до REST API за допомогою асинхронних запитів `fetch` і навчилися обробляти JSON-відповіді сервера. Реалізували перевірку форми на клієнті та показ зрозумілих повідомлень про успіх, помилки валідації й проблеми з мережею. Дані товарів додаються до сторінки через текстові DOM-властивості, тому введений HTML відображається як текст. Адаптивні картки, індикатор завантаження та стилі для світлої й темної тем роблять демонстрацію зручною на різних екранах.
